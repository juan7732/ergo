# ergo v0.6.0

Released: unreleased

Search grows a hand-friendly mode and a machine-friendly one. Upgrade with
`brew upgrade ergo` or `ergo update`.

## New: `ergo search` with no arguments is an interactive picker

`ergo search` without a query used to fail with a bare argument-count error.
It now opens a live-filter picker over every repo, folder, and workspace you
have declared, across all workspaces. Type to narrow the list (fuzzy, over
names, URLs, and workspace names), move with the arrow keys, and press Enter.

```
search: cor
> corvo  repo  ergo-ecosystem  cloned
  corvo-docs  repo  ergo-ecosystem  cloned
```

Enter prints the selection's absolute path to stdout and nothing else; the
picker itself draws on stderr. That makes search a navigation verb:

```sh
ergocd-search() { local d; d=$(ergo search) && cd "$d"; }
```

- Keep the `&&`. Esc or Ctrl-C cancels with nothing on stdout and exit code
  1, so the wrapper stays put instead of running `cd ""`.
- The path is printed even for targets not on disk yet (an uncloned repo, an
  unsynced workspace): it is the same projected location the JSON `path`
  field reports, and a failing `cd` tells you to sync first.
- The picker only starts when stdin is a terminal. Piped or scripted
  invocations without a query get a one-line usage error on stderr and exit
  1 immediately; they never block and never render.

`ergo search <query>` is unchanged.

## New: `ergo search --json` with no query returns the full index

One call now yields every entry across all workspaces, with `"query": ""`
marking the document as unfiltered:

```sh
ergo search --json | jq -r '.results[] | select(.kind == "repo") | .path'
```

The document shape is identical to a query's; this is an additive change to
the JSON contract. Agents and the VS Code extension can build a complete
picker from it without enumerating workspaces themselves.

## Improved: `ergo add repo` and `ergo add folder` take `--sync`

Adding a repo from a script or an agent session used to be two steps: the
add, then a separate `ergo sync`, with a `sync workspace now? [y/N]` prompt
in between whenever stdin looked like a terminal. The shorthand forms now
carry the intent in one call:

```sh
ergo add repo https://github.com/owner/repo.git --group=core --sync   # add and clone
ergo add folder scratch --sync                                        # add and create
ergo add repo https://github.com/owner/repo.git --sync=false          # add, never prompt, never sync
```

- **Default: nothing changes.** Without the flag the command behaves exactly
  as before: it prompts when stdin is a terminal and skips silently when it
  is not.
- `--sync` runs the sync immediately, no prompt, whether or not stdin is a
  terminal. `--sync=false` never prompts and never syncs.
- The sync runs unfiltered, never inheriting `--name`, `--group`, or
  `--tags` from the add.

While looking into this we verified the prompt gate itself: with piped stdin
(`printf '' | ergo add repo ...`) the shorthand has always added silently.
The prompt some agent harnesses saw comes from running commands on a
pseudo-terminal whose input ends at once, which no stdin check can tell from
a person at a keyboard. `--sync=false` is the answer for those environments.

## Fixed

- The "is stdin a terminal?" check that gates interactive prompts treated
  `/dev/null` as a terminal, because it only tested for a character device.
  `ergo add repo <url> </dev/null` therefore still printed the
  `sync workspace now? [y/N]` prompt. The check is now a real isatty test, so
  prompts and the new search picker stay silent whenever stdin is not an
  interactive terminal.
