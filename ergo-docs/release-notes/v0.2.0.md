# ergo v0.2.0

Released: 2026-07-31

The first release since ergo landed on Homebrew. Existing installs can upgrade
with `brew upgrade ergo` or `ergo update`.

## New: `[git] protocol` setting — SSH support without username prompts

If you authenticate to git hosts with SSH keys, ergo previously still cloned
over HTTPS (the transport is chosen by the URL in your workspace TOML), so git
would stop and ask for a username on every clone. You can now opt into SSH
globally:

```toml
# ~/.ergo/config.toml
[git]
protocol = "ssh"
```

With `protocol = "ssh"`, ergo rewrites `https://` repo URLs to scp form
(`https://github.com/o/r.git` → `git@github.com:o/r.git`) **in memory at clone
time**. Details:

- Works for any host: GitHub, GitLab, Bitbucket, self-hosted.
- Your workspace TOML files are never modified.
- URLs that can't be safely rewritten pass through unchanged: explicit ports,
  embedded credentials, `ssh://`, `git://`, `file://`, local paths, and URLs
  already in scp form.
- The default (`protocol = "https"`, or no `[git]` section at all) leaves every
  URL exactly as written — upgrading changes nothing until you opt in.

Note: repos cloned before enabling this keep their original HTTPS `origin`
remote. Migrate an existing checkout with
`git remote set-url origin git@github.com:owner/repo.git`, or delete the
directory and re-sync.

## Improved: git auth failures fail fast with a hint

Ergo-initiated git commands now run with `GIT_TERMINAL_PROMPT=0`. A repo that
needs credentials no longer hangs sync on a bare `Username:` prompt (which
could interleave across parallel clones); instead it fails cleanly per-repo
with a remediation hint, e.g.:

```
✗ private-repo   cloning https://github.com/o/private-repo.git: fatal: could not
  read Username for 'https://github.com': terminal prompts disabled (hint: git
  needs credentials for HTTPS; if you use SSH keys, set protocol = "ssh" under
  [git] in ~/.ergo/config.toml)
```

SSH failures (`Permission denied (publickey)`) get a matching hint pointing at
ssh-agent. Non-interactive credential helpers (VS Code,
git-credential-manager) continue to work — only terminal prompting is
disabled, and only for ergo's own git commands; `ergo run` is unaffected.
