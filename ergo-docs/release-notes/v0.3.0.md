# ergo v0.3.0

Released: 2026-08-01

The machine-readable release. This version ships the CLI contract the
upcoming ergo VS Code extension builds on — the extension will pin
**ergo >= v0.3.0** as its minimum supported version. Upgrade with
`brew upgrade ergo` or `ergo update`.

## New: `--json` on status, list, validate, and show

Each command can now emit a single JSON document on stdout — no ANSI, no
tables, no prose. Warnings still go to stderr as plain text, and exit codes
are unchanged from the human-format paths.

```sh
ergo status --json      # per-repo branch/dirty/behind/uncloned/group/tags
ergo list --json        # workspaces with repo counts and synced state
ergo validate --json    # valid flag + structured field/message errors
ergo show --json        # the active view filter, or null (read-only)
```

Details worth knowing:

- `status --json` includes each repo's `tags` (new — the human table is
  unchanged). Filter flags compose, and standalone-repo mode emits the same
  shape with an empty workspace name.
- `validate --all --json` wraps per-workspace results in one document; a TOML
  that fails to parse reports a single error with an empty `field`.
- `show --json` is read-only: it prints the filter recorded in the
  `.code-workspace` and modifies nothing. Combining it with a mutating show
  (`show ml --json`) is rejected.
- The schemas are a stable contract: fields never change or disappear;
  future evolution is additive only. See the "JSON output contract" section
  in `ergo-docs/03-commands.md`.

## Fixed: sync and open no longer reset an active show filter

Previously, running `ergo sync` or `ergo open` regenerated the
`.code-workspace` with the full folder list, silently clearing any view you
had set with `ergo show`. Both commands now read the recorded filter back and
re-apply it, so your focused view survives the daily workflow until you run
`ergo show all`.

The filter remains purely a view concern: repos hidden by it are **still
cloned and pulled** by sync — only the explicit `--name`/`--group`/`--tags`
flags narrow the operation set. So it's never silently in effect, an active
filter is surfaced with a note line on sync, open, and human-format status:

```
note: show filter active (group "ml") — 3 of 12 repos visible; run 'ergo show all' to clear
```

A malformed `.code-workspace` falls back to the old behavior (regenerate
unfiltered) rather than failing the sync.

## Internal

- New `internal/output` package owns the JSON wire format as dedicated
  structs with golden-byte tests, so internal refactors can't silently change
  the contract.
- New `vscode.ReadFilter` — the read counterpart to `Generate` — with
  round-trip tests; unknown fields in the workspace file are tolerated.
- Nine new dockerized integration tests covering every `--json` flag
  end-to-end and the filter-preservation semantics.
